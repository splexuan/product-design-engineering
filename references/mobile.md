# 移动端软件设计要点

设计手机或平板体验时阅读本指南。先确定目标操作系统、设备类型、使用情境、网络假设，以及产品属于原生、混合还是 Web 应用。

## 需要考虑的设计决策

- 优先支持用户短时间内需要完成的任务，并让下一步操作清楚可见。
- 针对窄屏和触控操作调整信息层级；不要简单缩小桌面布局。
- 当操作系统惯例能提升可预测性时，采用对应的导航、手势、底部面板、权限申请和系统控件。
- 让触控区域足够大、间距合理、手势宽容。重要功能不能只靠手势触发或发现。
- 按需考虑单手操作范围、打断、键盘弹出、安全区域、屏幕旋转和不同尺寸。
- 在用户需要相关能力时再申请设备权限，说明用途，并妥善处理拒绝授权的情况。

## 交互与状态

- 在实际可行的情况下，用户切换应用、受到打断或遇到可恢复的网络故障后保留进度。
- 清楚呈现离线、加载、重试、空数据、成功和权限状态。
- 选择性使用确认；说明破坏性操作的后果，并在可行时提供恢复方法。
- 尊重辅助功能设置、文字缩放、屏幕阅读器、对比度需求和减少动态效果的偏好。
- 只有在触觉反馈、动画或通知能够传递有意义的信息，或用户明确需要时才使用。

结合目标平台和产品情境检查方案；不同移动操作系统的惯例并不通用。
