# Web 产品设计要点

设计或改动浏览器产品流程时阅读本指南。先了解产品现有导航、组件库、响应式规则和用户预期。

## 需要考虑的设计决策

- 保持方向感：用户应当知道自己身处何处、发生了什么变化、下一步可以做什么。
- 结构应服务任务。只有在确实省力时才加入导航、搜索、筛选和上下文操作，不要因为其他产品有这些功能就照搬。
- 明确页面目的、主要操作、辅助信息和次要操作之间的视觉层级。
- 对信息密集的数据，确保用户能理解如何浏览、比较、筛选、排序，以及如何处理无结果的情况。用户调整视图时尽量保留有用上下文。
- 响应式布局应根据任务优先级和内容关系调整，而不只是缩小桌面页面。
- 只有当用户需要在不同区域间移动时才使用持久导航。避免导航层级过深，妨碍常用任务。

## 交互与状态

- 有意识地设计加载、空数据、错误、成功、禁用和权限状态。
- 对可恢复的错误或常规导航，尽可能保留用户输入和上下文。
- 在相关控件旁解释校验问题，并提供清晰的恢复方法。
- 当操作后果不明显时，为破坏性或重要操作提供确认；若撤销更安全、更方便，可优先提供撤销。
- 确保控件支持键盘和辅助技术，并提供可见焦点与有意义的标签。
- 动效不应拖慢任务或遮盖状态变化；相关场景下尊重减少动态效果的系统偏好。

以这些要点辅助判断，并结合产品真实用户和约束进行验证。
