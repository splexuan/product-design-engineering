# 开发者工具设计要点

设计 IDE、终端、API 客户端、基础设施工具、代码助手及其他技术工作软件时阅读本指南。用户的经验水平可能不同；应围绕其任务和熟悉程度设计，不要默认所有人都是初学者或专家。

## 需要考虑的设计决策

- 在用户执行或应用操作前，让重要状态、影响范围和后果清楚可见。
- 按需通过搜索、键盘操作、命令发现、批量操作和可复用配置提升高频流程效率。
- 必须使用领域术语时，在用户遇到术语的地方解释不熟悉的概念。
- 清楚区分预览、试运行、应用和破坏性操作。让用户容易核对目标环境和受影响资源。
- 提供有用的诊断信息，说明原因、受影响项目和下一步恢复办法。
- 让熟练用户能够快速操作，同时保持基础功能易于发现和理解。

## 交互与状态

- 保留用户编写的配置，并说明自动编辑会影响哪些内容。
- 对耗时操作显示进度和部分结果；明确取消和重试的行为。
- 处理空项目、凭证或权限缺失、服务断开、数据过期和部分失败。
- 保证键盘焦点和快捷键可靠；状态表达不能只依赖颜色。
- 对命令式界面，让语法错误可操作；在后果较重时，执行前提供易懂的预览或生成命令。

根据操作后果和用户任务，采用相称的保护措施。
